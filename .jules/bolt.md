## 2025-03-03 - Optimizing consolidated user order history with parallel queries and compound indexes
**Learning:** Sequential `await` statements on independent database collections (such as active and delivered orders) block the event loop needlessly, compounding query latency. Combining them into `Promise.all` executes them in parallel, nearly halving endpoint response time. Furthermore, queries combining filters with sorted results (e.g., sorting delivered orders by date) trigger expensive MongoDB in-memory sorts unless a compound index matching `{ filterField: 1, sortField: -1 }` is defined.
**Action:** Always scan API routes for sequential, non-dependent database queries and parallelize them. Pair query optimization with corresponding single-field or compound Mongoose indexes on the schema level to avoid unindexed table scans.

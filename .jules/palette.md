## 2025-11-23 - Refactoring Non-Semantic Interactivity inside Navbars
**Learning:** Hardcoded `div` tags used as interactive elements lack native keyboard focusability, default hover styles, and correct screen reader exposure. Standardizing on `<button type="button">` is extremely resilient but requires resetting the browser's default button styles (such as `border: 'none'`, `background: 'none'`, and `padding: 0`) to preserve pre-existing layout spacing and visuals. Also, adding `pointer-events: 'none'` on nested Lottie animations guarantees that click events bubbling from pointer devices correctly hit the keyboard-focusable button element without target obstruction.
**Action:** Always replace interactive `div` elements with `<button type="button">` rather than just adding `tabIndex={0}` and ARIA attributes, resetting borders, padding, and background explicitly to prevent design breakage.
